# Tallow Engine Architecture

## Build, run, and compile shaders

- Engine, editor, launcher and player are Beef with a C/C++ native layer. Gameplay and its managed toolchain are C# 15 on .NET 11 (`global.json`, `BeefSpace.toml`, `native/CMakeLists.txt`, `Managed/Tallow.API/Tallow.API.csproj`).
- Source build needs Python 3.11+, CMake 3.20+, Ninja, a C/C++20 toolchain, Git, `BeefBuild` on `PATH` or `BEEFBUILD`, and the SDK from `global.json`. First native configure fetches pinned Jolt (`README.md`, `tools/build.py`, `native/CMakeLists.txt`).
- Linux x64 build and launch use `./build.sh --config Debug` and `./build/Debug_Linux64/TallowLauncher/TallowLauncher`.
- Windows x64 build and launch use `python tools\build.py --config Debug` and `build\Debug_Win64\TallowLauncher\TallowLauncher.exe` from an x64 Visual Studio developer shell with `clang-cl`.
- macOS Intel uses the native build and packaging sequence in `.github/workflows/release.yml`. Build Rapier if needed with `python3 tools/build_rapier.py --platform macos`, then run `python3 tools/patch_textedit.py`.
- macOS native configure uses `cmake -S native -B build/native -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_OSX_DEPLOYMENT_TARGET=12.0 -DCMAKE_C_COMPILER=/usr/bin/clang -DCMAKE_CXX_COMPILER=/usr/bin/clang++`.
- macOS native build uses `cmake --build build/native --target tallow_native bgfx bimg bimg_decode bx SDL3-static joltc Jolt enet shaderc texturec tallow_modelsettings tallow_modelconv`.
- macOS package and launch use `python3 tools/package_engine.py --platform macos --folder dist/Tallow-macOS` and `./build/Release_macOS/TallowLauncher/TallowLauncher` (`Launcher/BeefProj.toml`).
- Pass `--create /path/to/MyGame --showcase`, `--open /path/to/MyGame`, or `--build-project /path/to/MyGame` to the launcher to create, open, or compile a game (`Launcher/src/Program.bf`).
- Build gameplay without opening the editor using `dotnet run --project Managed/Tallow.Build/Tallow.Build.csproj -- --project /path/to/MyGame --engine-root .`.
- Export from File > Build or run `dotnet run --project Managed/Tallow.Build/Tallow.Build.csproj -- export /path/to/MyGame --output /path/to/export --engine-root .`. The standalone `TallowPlayer` accepts `--game /path/to/export` (`Managed/Tallow.Build/Export/Exporter.cs`, `Player/src/Program.bf`, `Engine/src/Core/GameMain.bf`).
- Compile shipped shaders with `python3 tools/compile_shaders.py` or `./tools/compile_shaders.sh`. Select targets with repeatable `--backend spirv`, `--backend glsl`, `--backend essl`, `--backend webgl`, or `--backend metal`. `SHADERC` overrides the locally built compiler.
- Shader builds read `Engine/shaders/varying.def.sc` and the includes in `Engine/shaders/include/`. `tools/compile_shaders.py` generates the `fs_cluster` variant from `Engine/shaders/fs_mesh.sc` and writes `Engine/assets/shaders/<backend>/`. The WebGL build skips compute and cluster-pulling shaders.

- Networked Day / Night (N4a) — `Engine/src/Scene/DayNightNetwork.bf`: with `Scene.Network` not Offline the server owns the clock (start time/tick, speed, paused, enabled and the sky's static settings), sent reliably in `NetworkSync.MsgEvent` under the `\x02daynight` marker on session start, on a join (hooked in `NetworkSync.ClientJoined`/migration reclaim) and only when a setting changes; every peer works the time from `NetworkManager.ServerTick - 1` (`DayNightNet.SharedTick`) so a client that joins late is on the server's time at once; the sky is drawn `InterpolationAlpha` ahead of it. `ClockState.epoch` marks every rebase (start, pause/pace change, the time set, a client taking the state) so events skip the jump. - C# Day / Night (N4b) — `Engine/src/Scene/DayNightEvents.bf` queues sunrise, sunset and each whole hour crossed by the shared clock (simulation time above), stamping each with `DayNightNet.EventTick` from the clock's own settings so every peer gets the same tick; a tick step over 240 ticks or a new epoch is a jump and fires nothing. `Engine/src/Scripting/CSharpDayNightApi.bf` + `Managed/Tallow.API/DayNight.cs` (`TimeOfDay`, `DayLengthMinutes`/`DayLength`, `Speed`, `Paused`, `Latitude`, `AxisTilt`, `NorthDirection`, `DayOfYear`, `IsNight`, `SunDirection`/`SunColor`/`SunIntensity`, `MoonDirection`/`MoonPhase`/`MoonIllumination`, `OnSunrise`/`OnSunset`/`OnHour`, `LastEventTick`; polled on `GameThread.EachFrame` like `AntiCheat.OnViolation`). `SceneEnvironment` gained C# `SkyBrightness`/`StarBrightness`/`AutoColors`/`SunIntensity`/`NightSkybox`; `Scene.Clear` calls `DayNightEvents.Forget`.
- Volumetric fog (V3a-V3d) — `Engine/src/Render/RenderViewVolumetric.bf` fills a view-aligned froxel grid (`cs_vfog_inject.sc` from the height fog, the `FogVolume` boxes and balls (`Engine/src/Render/FogVolume.bf`, at most `RenderResources.FogVolumeMax` 32 through `u_fogVolumes`), the sun through the cascades, the sky ambient and the point/spot lights by cluster with their shadow tiles, `include/vfog_local.sh`), sums it outwards (`cs_vfog_integrate.sc`) and lays it over the solid scene and sky from the depth pass (`fs_vfog_apply.sc`); shared maths in `Engine/shaders/include/vfog.sh`, draw constants in `RenderResources`. Cell size, depth, temporal blend and local-light budget are quality values (`RenderView.FogTileSize`/`FogSlices`/`FogTemporalAllowed`/`FogLocalLights`, set by `Quality.Apply`, Low off); `--gpu-debug-view fog-density|fog-light` shows the cells. Where compute is missing (OpenGL, the web, `--gpu-driven-caps-off`) `fs_vfog_fallback.sc` draws the same height fog as an exact ray integral with screen-space sun shafts from the depth pass, and Fog Volumes are left out. Temporal: the cells are sampled at a jittered depth each frame and blended with last frame's cells reprojected by `u_vfogPrevViewProj` (`RenderView.FogTemporalEnabled`, 0.9 or 0.95 on Ultra). See-through things and water, drawn after the apply, read the sums in-shader (`fs_mesh_vfog`/`fs_water_vfog` variants of fs_mesh/fs_water, `vfogSampleWorld`, `RenderResources.MeshVFogProgram`/`WaterVFogProgram`); particles are covered by the apply. Per-light scattering is `Light.volumetric` (in LightClusters' texel 4 w). `SceneEnvironment.volumetricFog`/`vfDensity`/`vfHeight`/`vfFalloff`/`vfAnisotropy`/`vfAlbedo`/`vfSunScattering`/`vfAmbient`/`vfDistance`; Vulkan/D3D/Metal only for the grid. Test `--vfog-test` (`VolumetricFogTest.bf`, which also checks the fallback with `--gpu-driven-caps-off`); profiler counters "GPU Time: Volumetric fog", "Volumetric Fog Cells", "Volumetric Fog Local Lights"; benchmark `--gpu-bench fog`.
- Clouds (C1c, C2a, C2b, C2c, C2d) — `Engine/src/Render/Clouds.bf` owns the weather clock (`Clouds.Seconds`: the networked simulation clock or the local clock; `Clouds.OverrideSeconds` pins it for tests) and the wind + seed offset, so peers agree with no network state. `PhysicalSky.SetCloudUniforms` pushes the scene's `cloud*` settings into the shared block in `Engine/shaders/include/clouds.sh` (`u_cloudShape`/`Wind`/`Light`/`View`/`Tint`/`SunDir`/`SunColor`/`MoonDir`/`MoonColor`/`Ambient`/`Steps`); `skyColor` in `sky_physical.sh` draws the 2D procedural layer over the sun/moon/stars, fading near the horizon, and both `fs_sky_physical.sc` and the reflection cube (`fs_env_sky_physical.sc`) use it. The cube re-makes when the cloud settings or the wind (quantised to 128 m) change (`Reflections.SkyState`). Gradient and full Custom skyboxes are untouched. Volumetric clouds (C2a): `Engine/src/Render/RenderViewClouds.bf` marches the slab between `cloudHeight` and `cloudHeight + cloudThickness` in `cs_clouds.sc` into a RGBA16F target at `cloudResolution` (default half res), dispatched in the camera's fog-inject view (all 28 per-view ids are taken); the density is the shared weather map eroded by 3D FBM detail (`cloudDensity` in `clouds.sh`), summed front-to-back with the fog's energy-conserving form. The sky samples that target at `v_texcoord0` (`cloudLayer`), so clouds are behind all geometry; the cube, captures and planar views keep the 2D layer, and OpenGL/GLES/WebGL plus `--gpu-driven-caps-off` fall back to it. Cloud lighting (C2b) in `cloudLighting` (`clouds.sh`): an optical depth toward the brighter of the sun and the moon (4 steps, `RenderView.CloudShadowSteps`, capped at `cloudThickness`, early-out past exp(-8)) for Beer-Lambert self-shadowing and silhouettes; a two-lobe Henyey-Greenstein phase (g = `cloudAnisotropy`, back lobe -0.3 at 25%); a powder term (`u_cloudLight.z` = 8/m); a near-isotropic 0.3 multiple-scattering term; and the sky/ground ambient desaturated toward its luminance and lifted 3x. The sun's radiance is the sky's own (`u_cloudSunColor` = air transmittance x sun intensity x sky brightness), so clouds follow Day / Night. Temporal and performance (C2c): two targets swap each frame; the march's start is jittered by a 32x32 blue-noise tile (`RenderResources.BlueNoise`, Ulichney void-and-cluster) shifted by a low-discrepancy offset each frame, and the layer is blended with last frame's reprojected by the slab midpoint minus the wind drift into last frame's view-projection (0.85 history, 0.6 with TAA), dropped on a camera cut (5 m or ~30 degrees), a skipped frame or a resize (`RenderView.CloudHistoryValid`); the blend reads the history at sampler stage 5 because bgfx compute bindings share the unit space with the storage image at 0. The step count, shadow steps, temporal switch, resolution cap and distance cap are quality values (`Quality.bf` Low/Medium/High/Ultra; Low forces the 2D backup), set from the editor's Graphics Quality window and round-tripped by `--quality-test`; `--gpu-debug-view clouds` writes the cloud field (the column's opacity in red, its average light in green and the marched step share in blue, with the temporal history dropped); profiler counters "GPU Time: Volumetric clouds", "Volumetric Cloud Pixels" and "Volumetric Cloud Rays". Renderer integration (C2d): the sky is drawn first with depth LEQUAL, so solid geometry drawn after it covers the clouds (terrain and buildings hide them with no extra work); the sky's own bodies are drawn before the cloud composite, so a thick cloud hides the sun's disc, the moon and the stars; the reflection cube, captures and planar views keep the 2D layer (the cube's `SkyState` includes the cloud settings and the wind quantised to 128 m); the Custom skybox's `TW_SKY_BLEND` path samples the same screen layer through `skyColor`, and without Skybox Blend the skybox replaces it; `--gpu-driven-caps-off` (and a scene in 2D mode, Low, or a device without compute) draws the 2D backup with no raymarch. Tests `--cloud-test sky` (2D), `--cloud-test volume` (clear/broken/overcast), `--cloud-test lighting` (noon away/toward the sun, sunset, night, sun behind an overcast deck), `--cloud-test temporal` (still, cut, pan, ray-count view, budget) `--cloud-test integration` (a building in front of the clouds, the sun behind a deck, a mirror ball's reflection cube, the fog and a Custom skybox with and without Skybox Blend; also run it with `--gpu-driven-caps-off`, which must draw the 2D backup) and `--cloud-test quality` (each preset's cloud budget, Low's 2D backup with no raymarch, and the density/light debug view). The GL/Web fallback (C3b) is a pure rule, `RenderView.VolumetricCloudsAvailable(renderer, compute, cs_clouds, capsOff)`: only Vulkan, Direct3D 11/12 and Metal raymarch, so OpenGL, OpenGL ES (which is what a page's WebGL reports) and `--gpu-driven-caps-off` draw the 2D layer; `--cloud-test settings --headless` checks that table with no window, and `--cloud-test fallback` draws it on any backend (pretending compute is missing where it exists): no cloud target or rays, the same picture as 2D mode, and Low selecting it too. The C# API (C3c) is `Scene.Environment.Clouds` (`CloudSettings` in `Managed/Tallow.API/Environment.cs`: Enabled, Mode, Coverage, Density, Altitude, Thickness, WindSpeed, WindDirection, Seed, Anisotropy, Ambient, Tint, Distance, Resolution) over the existing reflection-free `CSharpEnvironment.Get`/`Set` cases 46-59, so the allowlist does not grow. The clouds need no network state: `Clouds.Seconds` is the server-owned simulation clock and the seed is a whole number of metres, so peers with the same scene agree on the weather; `--cloud-test network` plays a host, a client and a late joiner on loopback with no window and checks the weather offset (and so the coverage) agrees within a tick, including while the Day / Night clock is paused.

## Core data, GPU layout, and frame order

- `Scene` owns a Flecs `World`, scene objects, physics, and Tick, Frame and Replay pipelines (`Engine/src/Scene/Scene.bf`). `GameObject` maps to a Flecs `Entity`, whose 64-bit ID includes generation and reserves zero for null (`Engine/src/Scene/GameObject.bf`, `Engine/src/Ecs/World.bf`).
- `RenderItem` links mesh, renderer, material, transform, bounds, tint and lighting selections. The `[CRepr]` `InstanceData` is a 64-byte matrix followed by a 16-byte color (`Engine/src/Render/RenderView.bf`).
- The `[CRepr]` `MeshVertex` has a 44-byte stride with position float3, normal float3, packed normalized RGBA8 (`0xAABBGGRR`), UV float2, and UV2 float2. Match `Gfx.MeshLayout` and `Engine/shaders/varying.def.sc` when editing (`Engine/src/Render/Gfx.bf`).
- CLOD buffers use raw 32-bit words. The backing bgfx buffer element is four words (16 bytes), with pool sections padded to four-word boundaries. Vertices, clusters and groups use 11, 16 and 8 words respectively (group: sphere xyz+radius, resident flag, feedback group id). Pool offsets are word addresses. Packed triangle offsets are byte addresses (`Engine/src/Render/GpuDriven.bf`, `Engine/shaders/include/clod.sh`).
- A 44-word CLOD instance carries the current matrix and color, three previous matrix rows, current bounding sphere, cluster base/count, bin/flags and scale, and previous sphere center plus padding. Bin occupies low 16 bits and bit 16 disables cone culling (`Engine/src/Render/GpuDrivenView.bf`, `Engine/shaders/include/clod.sh`).
- A cluster has at most 128 triangles (384 corner indices). Visible data has a 256-word bin-offset header followed by `(instance, cluster)` pairs. Control, work nodes, deferred lists and indirect commands have separate buffers. Preserve shader constants and binding slots when changing their layout (`Engine/src/Render/GpuDriven.bf`, `Engine/src/Render/GpuDrivenView.bf`, `Engine/shaders/include/clod.sh`).
- Virtual geometry (M4b) — `Engine/src/Render/ClusterPages.bf` cuts a `ClusterMesh` into ~64 KB pages (coarse groups first; page 0 = top of the hierarchy), cooked to `<name>.tclodp` (`PageFile`, `StreamKind.GeoPage`); meshes of <= 8 pages load whole. The cluster/group table stays resident; a page (vertices, vertex lists, triangles) is a `MeshEntry` `IStreamConsumer` upload; a group is drawable (resident flag) only when its page and all parent pages are live, eviction cascades to child pages, and `cs_clod_clusters.sc` draws the coarsest resident ancestor and sets a "wanted" bit. `GpuDriven.PollFeedback` reads the used/wanted bitmaps (`b_feedback`, slot 7) every few frames and requests pages parents-first. Test: `--streaming-test geometry` (`GeometryStreamTest.bf`); `--no-geometry-streaming` loads every page whole.
- Pool allocation stores resident cluster geometry and reuses freed spans after in-flight frames clear. Per-view transient buffers rotate across three slots. Worker-built clusters use `<project>/.cache/clod` and upload on the main thread (`Engine/src/Render/GpuDriven.bf`, `Engine/src/Render/GpuDrivenView.bf`, `Engine/src/Render/ClusterMesh.bf`).
- Local lights use 16×9×24 clusters. CPU light, shadow-tile and cluster-list data must match the `RGBA32F` texture layout read by `Engine/shaders/include/lighting.sh` (`Engine/src/Render/LightClusters.bf`).
- `Application.Frame` polls events/input, advances time, runs up to eight accumulated fixed ticks, publishes interpolation alpha, runs the variable update, renders, and calls `bgfx.frame(0)`. Headless frames run simulation and updates with a short sleep in place of presentation (`Engine/src/Core/Application.bf`).
- Scene tick — pending starts, network receive, fixed-pipeline systems and updates, navigation and saved transforms, water and physics step, contact dispatch, network send (`Engine/src/Scene/Scene.bf`).
- Scene frame — `OnFrame` and audio, pending starts, `EarlyUpdate`, `Update`, queued navigation paths, `LateUpdate`, managed continuations, viewmodel pose, IK/skinning and deferred destruction (`Engine/src/Scene/Scene.bf`). Game update polls packs and scene transitions before the scene update (`Engine/src/Core/GameApp.bf`).
- Camera render — prepare temporal state/lights, gather and cull, route eligible GPU items, sort, submit reflection and shadow passes, fill the volumetric fog's froxel grid, then opaque, depth, decals, the fog apply, water, transparency, underwater and viewmodel, screen effects, bloom and final tonemap. Preserve bgfx view ID dependencies and each camera's 28-view range (`Engine/src/Render/RenderView.bf`).
- Global bgfx order — skinning compute at view 1, CLOD cull at 2, first occluder draws at 3–4, first HZB and retests at 5, second occluder draws at 6–7, final HZB at 8, cameras from 10 (`Engine/src/Render/Compute.bf`, `Engine/src/Render/GpuDriven.bf`).
- Two-phase occlusion tests the previous HZB, draws survivors as occluders, retests deferred instances/clusters against fresh HZB, draws second-phase survivors, and saves both phases' occluders for next frame. Shadows use single-phase culling (`Engine/src/Render/GpuDrivenView.bf`, `Engine/src/Render/RenderViewGpu.bf`, `Engine/src/Render/GpuOcclusion.bf`).

## C# conventions and architectural invariants

- Gameplay classes derive from `Tallow.Script`. The build generates their registry for JIT and NativeAOT. Values serialized by the inspector are applied before `Awake`. Keep explicit `[SerializedFieldId]` stable across field renames and use `[FormerlyNamed]` for persisted script type renames (`Managed/Tallow.API/Script.cs`, `Managed/Tallow.Build/Program.cs`).
- ECS `[Component]` data is unmanaged and schema-registered by generated code. Its field order, sizes and `[Sync]` offsets are layout contracts. Managed ECS data attaches to allowed entities, and managed deletion only applies to locally owned bare entities (`Managed/Tallow.API/EcsData.cs`, `Managed/Tallow.API/EcsSystems.cs`, `Engine/src/Ecs/World.bf`).
- Preserve scene/session IDs and entity generation checks when using managed value handles. Use the world on the main thread. Within `Query.ParallelFor`, workers operate only on their chunk columns. Keep Scene pipelines non-reentrant (`Managed/Tallow.API/Script.cs`, `Engine/src/Ecs/World.bf`, `Engine/src/Ecs/Query.bf`, `Engine/src/Scene/Scene.bf`).
- Keep interop changes synchronized across `[CSharpExpose]`, the binding manifest, generator and version check. Generated native wrappers and `Managed/Tallow.API/Generated/CSharpBindings.g.cs` are build outputs. Preserve Cdecl signatures and sequential blittable layouts at the boundary (`Engine/src/Scripting/CSharpExpose.bf`, `Engine/src/Scripting/CSharpBindingManifest.bf`, `Managed/Tallow.BindingGen/Program.cs`, `Managed/Tallow.API/GeneratedNativeApi.cs`).
- Keep managed output paths platform-independent (`Managed/Directory.Build.props`). Use pack-aware asset reads and project-relative asset paths in runtime code (`Engine/src/Assets/AssetPack.bf`, `Engine/src/Assets/Assets.bf`).
- Coordinate system is left-handed with +X right, +Y up, +Z forward and clockwise mesh fronts. Native `Matrix4` is column-major with column vectors (`Projection * View * Model * v`). Managed gameplay uses `System.Numerics` and Tallow's math extensions (`Engine/src/Math/Matrix4.bf`, `Engine/src/Render/Mesh.bf`, `Managed/Tallow.API/MathExtensions.cs`).
- GPU-driven drawing requires Vulkan or Metal, compute and indirect draw support, and loaded backend shaders. Retain ordinary rendering for pending clusters, unsupported materials, moving vertices, viewmodels, capture/planar views, and unsupported devices (`Engine/src/Render/GpuDriven.bf`, `Engine/src/Render/RenderViewGpu.bf`).
